Ship of Theseus

Does a codebase remain the same if every line is replaced? A monthly pulse on software entropy.

Python 3.12+ Vanilla JS GitHub Pages GitHub Actions Black Style
GitHub Repository Live Deployment Documentation

The Philosophy & Problem

  • The Challenge: Software projects constantly evolve. A repository can live for decades, developers leave, and architectures shift, making it hard to track codebase churn and the survival of original code.
  • The Solution: A visualization engine that measures codebase entropy through the lens of the Ship of Theseus paradox. It tracks when lines of code were written and how long they survive.
  • The Outcome: Provides a visceral, data-driven understanding of codebase health, helping teams identify "fossils" (oldest surviving lines of code) and track the true timeline of major rewrites and architectural shifts.

Architecture & Internals

The system separates the data generation (Python) from the frontend display (Vanilla JS), communicating strictly via static JSON files. This allows the entire dashboard to be hosted serverlessly on GitHub Pages.

1. The Data Pipeline

To maximize performance, the pipeline invokes the native git binary directly rather than relying on Python wrappers. The extraction works incrementally, skipping months that have already been analyzed.

flowchart TD A[Start: read `theseus.config.json`] --> B{Has Data File?} B -- No --> C[Full Clone & 1st Commit] B -- Yes --> D[Look at Last Snapshot Date] D --> E[Is Last Snapshot < Current Month?] E -- Yes --> F[Clone & Jump to Next Month] E -- No --> G[Skip: Up to Date] C --> H[Run Git Blame Parallel] F --> H H --> I[Count Lines by Authorship Year] I --> J[Append Snapshot to JSON]

For parallelization, it uses ThreadPools to run git blame --line-porcelain concurrently across all tracked files, using Regex to extract line ages.

2. Fossil Extraction

Fossils (pointers to the oldest surviving code) are calculated independently. The Genesis protocol finds the first line of code pushed to history, while the Survivor protocol recursively blames HEAD to find the oldest line still in use.

3. Data Delivery (UI)

The UI fetches the configuration and dynamically builds the repository selection grid. When a repository is clicked, it fetches the corresponding dataset asynchronously and renders the D3.js chart.

DevOps & CI/CD

The system uses GitHub Actions to run automated monthly updates on configured repositories. The primary workflow generates incremental JSON snapshots and automatically commits the new data back to the repository.

The pipeline execution consists of three main phases: Bootstrapping (cloning and configuration), Analysis (incremental snapshots and updating survivor fossils), and Persistence (minifying data payloads and committing diffs back to the origin).

To optimize for CI environments, the pipeline only evaluates missing months and updates the "Living Fossil" pointer without re-evaluating the entire historical genesis. Once changes are generated, a bot commits and pushes the updated payloads to main.

Quick Start

You will need git, python (3.12+), and poetry.

git clone https://github.com/Asifdotexe/Theseus.git
cd Theseus
poetry install

# Run full analysis
poetry run python scripts/analyse_repository.py
